## How To Read This Plan

Each step is a prompt for a code-generation LLM.
Feature steps follow RED, GREEN, REFACTOR and test application logic only, never framework or library behavior.
Task steps follow Scope, Tooling, Do, Verify, Document, for wiring, config, porting, and docs.
Task steps carry a `(task)` marker in the title; Feature steps carry no marker.

### Porting Convention

Steps that port from the private source read the `claude-code-plugin-private` repo (a sibling directory of this repo) at commit `2806854`, never its working tree.
In every porting command, `<private>` is that sibling checkout; the executor resolves the path locally and never commits it.
Read a file with `git -C <private> show 2806854:<path>`.
List the private tree with `git -C <private> ls-tree -r --name-only 2806854`.
Apply the Component F port rules (spec lines 282 to 304) to every ported skill, reference, fixture, and eval.

### Fences This Plan Must Not Cross

From spec Invariants, Non-goals, and the Deferred list:

- The profile token ceiling stays at 5,000 in this phase.
  The raise to 10,000 is deferred python-branch work and no step implements it.
- No model pins or model guards anywhere: no `model:` frontmatter, no `disable-model-invocation:`, no instruction to check or switch the session model.
- A skill reaches its own files by relative path only.
  No `${CLAUDE_PLUGIN_ROOT}` and no `../` in any skill body.
- Shipped scripts under `src/scripts/` import only the Python standard library and run on Python 3.11 or newer.
- SKILL.md frontmatter carries exactly `name`, `version`, `description`, `compatibility`.
  `description` is at most 1,024 characters with no angle-bracket token; `compatibility` is at most 500 characters.
- No top-level `bin/` in the plugin.
  No hooks, no MCP servers, no HTML server, no Obsidian or vault sync stage, no PyPI package, no analytics.
- Versions are uniform across every SKILL.md, `plugin.json`, and `marketplace.json`.
  During beta the scheme is SemVer `0.x` (initial `0.1.0`); it flips to CalVer `YYYY.MM.DD` at the 1.0 maturity milestone.
  Versions move only on the maintainer's ruling.
- The private repo is never modified: every read of it is through `git show`.
- `src/` is the single source of truth; the copies under each skill are generated by sync and never hand-edited.

## Section 3: YAML Subset Parser

Goal G3, Component C.
A standard-library parser for the YAML subset the artifact formats and config files use.
Everything outside the subset is an error, never a guess.

**Tools:**
- Skills: python:python
- MCPs: none
- Linters: ruff check --output-format=json, mypy --strict

### Step 5: Implement yaml_subset.py

```text
1. RED: Write parser unit tests first, using inline string inputs (no fixtures yet):
   - Create tests/test_yaml_subset.py:
     - Test that a bare "key: value" pair parses to {"key": "value"}.
     - Test that a double-quoted and a single-quoted string both strip quotes.
     - Test that an integer value parses to an int, not a str.
     - Test that true, false, and null parse to True, False, and None.
     - Test that an inline list "[a, b]" parses to ["a", "b"].
     - Test that an inline map "{k: v}" parses to {"k": "v"}.
     - Test that a nested inline map inside an inline list (the archive categories shape) parses correctly.
     - Test that a block map by indentation parses to a nested dict.
     - Test that a "#" comment line and a trailing comment are ignored.
     - Test that an anchor ("&a"), a tag ("!!str"), a multi-document marker ("---" mid-stream), and a block scalar ("|") each raise an error whose message names the offending line number.

2. Document the subset:
   - Add a module docstring in src/scripts/yaml_subset.py that enumerates exactly the supported constructs and states that anything else is an error.

3. GREEN: Write minimal code to pass:
   - Create src/scripts/yaml_subset.py with a `parse(text: str) -> dict` entry point and a CLI guarded by `if __name__ == "__main__":` that reads a file argument and prints the parsed dict.
   - Standard library only. Type hints everywhere. Raise a ValueError naming the 1-indexed line on anything outside the subset.

4. RED: Add edge-case tests:
   - Test that an empty document parses to {}.
   - Test that duplicate keys raise rather than silently overwrite.
   - Test that a wrong indentation step under a block map raises with a line number.

5. GREEN: Extend the parser minimally to pass the edge cases.

6. REFACTOR: Factor the tokenizer and the value coercion into small typed helpers; keep the public surface to parse() and the CLI.

7. Update documentation:
   - Keep the module docstring's construct list in sync with what the tests cover.

8. Verify meaningful coverage of the parser logic and run `just check`.
```

## Implementation Guidelines

- Work on a feature branch through a pull request; only the maintainer merges to main.
- Version: SemVer `0.1.0` for this beta, stamped uniformly on every manifest and SKILL.md. The scheme flips to CalVer `YYYY.MM.DD` at the 1.0 milestone (a one-time jump; CalVer dates sort above `0.x`). Versions move only on the maintainer's ruling.
- `src/` is the single source of truth. Never hand-edit a file under metacognition/skills/*/references or .../scripts; change src/ and run `just sync`.
- Every ported skill, reference, fixture, and eval goes through the Component F port rules. A reviewer comparing against private main should find each private rule either present or removed by a named port rule.
- Shipped scripts under src/scripts import only the standard library and target Python 3.11. Dev tooling may have dependencies.
- Keep prose to the vendored writing rules: no em-dash or en-dash, straight quotes, Title Case headings, one sentence per line in committed markdown.
- When a decision is unresolved, list it under "Open questions" at the end of the step rather than guessing. The two review-time open items are settled: `~/.claude` wins the config tie-break over XDG, and the beta version scheme is SemVer `0.1.0`.
